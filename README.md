# Editorial Engine

Editorial Engine is a deterministic content-production pipeline built around locally generated fictional sources. It assembles long-form copy, an executive summary, three social posts, a newsletter, infographic concepts and SVG charts, citations, and named quality checks. It uses templates and explicit rules. It has no generative model and downloads no source material.

## Quickstart

Python 3.10 or newer is required. There are no runtime dependencies. Install the local CLI with:

```powershell
python -m pip install -e .
```

Generate the fictional papers, transcripts, memo, and dataset, then assemble a package:

```powershell
ee fixtures --out demo-sources
ee assemble --sources demo-sources --out demo-package
ee citations demo-package
ee qc demo-package
ee package demo-package --format html
```

The default fixture seed is `17`. Pass `--seed N` to `fixtures` or `assemble` to record a different seed. The planted values and templates remain fixed. Identical fixture inputs produce byte-identical package files. The append-only `ee-audit.jsonl` records a UTC timestamp, command, sources, outputs, QC results, and seed for each CLI run. The timestamp is intentionally the only per-run value in that audit trail.

`assemble` writes `editorial-package` by default and runs citations and QC as part of assembly. Its output contains the standalone Markdown pages, a self-contained copy of the fixture documents, a claims table, chart SVGs, and machine-readable reports. `package` combines the pages as Markdown or HTML. The HTML bundle includes the chart SVGs and repeats a provenance banner on each page.

## Architecture

```text
ee fixtures --out sources
        |
        v
synthetic source documents and fixture_manifest.json
        |
        v
ee assemble --sources sources --out package
        |
        +--> deterministic copy templates and claim IDs
        +--> SVG charts generated from pilot_metrics.csv
        +--> citations.md and claims_table.csv
        +--> qc_report.md and qc_report.json
        |
        v
ee package package --format md|html
        |
        +--> provenance banner on every rendered page
        +--> append-only ee-audit.jsonl
```

The implementation uses Python standard library modules only. The SVG charts are produced with deterministic text and geometry. No GPU or ML libraries are used.

## HONESTY BOUNDARY

All source material is synthetic fixture content generated by this pipeline. The fictional paper, interview transcripts, internal memo, and planted dataset do not describe real research, publications, organizations, or people. The QC layer never invents quotes, citations, or sources. Every citation points to a listed fixture document and includes a locator and source evidence. Quote verification searches the copied transcript text verbatim and fails if an expected quote is missing. No real publications are cited. Assembly is deterministic and QC is rules-based. There is no generative model.

The CLI, each editorial page, both rendered bundle formats, and each chart state the fictional nature and provenance of the content. These fixtures are demonstrations of the pipeline, not research findings.

## Citation semantics

Each factual sentence in editorial copy carries an inline claim reference such as `[C001]`. The `claims.json` record for that ID provides the claim text, fixture source ID, document locator, exact evidence lines, and output pages using the claim. Citation validation confirms that the source ID exists in the synthetic fixture manifest, the locator resolves, the evidence appears verbatim in that document, and every recorded claim is used in the copy. It also catches uncited prose sentences, unknown IDs, unused claim records, and invalid sources. `claims_table.csv` and the table in `citations.md` provide the human-readable mapping.

Quoted speech uses quote IDs such as `[Q001]`. A quote record names the fictional speaker, transcript source ID, and line locator. QC checks the full quote text against that transcript exactly. Rewording or inventing a quote causes a failure that reports the expected text and the actual text at the cited location.

## QC checks and pattern catalogue

The default generic-language threshold is zero matches. Use `ee qc <package-dir> --slop-threshold N` to allow up to `N` total matches. The report gives counts for every named pattern:

| Pattern name | Example phrase matched |
| --- | --- |
| `FAST_PACED_WORLD` | in today's fast-paced world |
| `DELVE_INTO` | delve into |
| `IMPORTANT_TO_NOTE` | it is important to note |
| `UNLOCK_THE_POWER` | unlock the power of |
| `GAME_CHANGER` | game-changer |
| `SEAMLESSLY` | seamlessly |
| `ROBUST_SOLUTION` | robust solution |
| `IN_CONCLUSION` | in conclusion |
| `LANDSCAPE_METAPHOR` | in the ever-changing landscape of |
| `TAPESTRY_METAPHOR` | weave a tapestry |

The `UNSUPPORTED_CLAIMS` check fails for uncited prose, claim IDs without a source record, unknown fixture IDs, invalid locators, or evidence that does not occur in the named fixture. The `QUOTE_VERIFICATION` check fails when an exact quote is absent from the named transcript. Any failed check makes the QC report fail.

## Demo walkthrough and expected QC report

Run the five quickstart commands. The generated fixture directory contains five fictional source documents plus a manifest. Assembly produces `article.md`, `executive_summary.md`, `social_posts.md`, `newsletter.md`, two infographic concepts, and two data-labelled charts. It then writes citation and QC reports.

For the unmodified fixtures, `ee qc demo-package` reports:

```text
GENERIC_AI_LANGUAGE: PASS
UNSUPPORTED_CLAIMS: PASS
QUOTE_VERIFICATION: PASS
```

The planted figures are 12.4 and 14.1 average focused hours per week, 9.2 and 7.8 reported interruptions per week, and 72 and 91 percent participation at baseline and week eight. The transcript quotes appear verbatim in the copy and can be found in their fictional source files. All claim references resolve to the local paper, memo, or dataset fixtures.
